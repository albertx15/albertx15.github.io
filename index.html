Deportdle — Juego deportivo diario en español

Somos dos entusiastas venezolanos apasionados por la tecnología. Juntos creamos y pusimos en producción un juego diario estilo Wordle en el que hay que adivinar el marcador exacto de partidos históricos reales. Cubre seis deportes: fútbol, NBA, NFL, MLB, LVBP y tenis.

Es un monorepo TypeScript con un sitio estático en Astro, una API en Hono y una base SQLite con casi 388 mil partidos. La respuesta nunca llega al navegador antes de tiempo, el sitio pasa auditorías de accesibilidad y cumple presupuestos estrictos de rendimiento.

01 · Diseño de Producto

Mecánica diaria adaptada a la naturaleza de cada deporte

Cada día se muestran dos equipos, la fecha y la fase de un partido histórico real. El jugador dispone de 6 intentos para deducir el marcador exacto guiándose por proximidad numérica y dirección.

Heurística de proximidad

Reglas compartidas

Cada número introducido se evalúa de forma independiente y se marca con color semántico más una flecha direccional (↑ o ↓) hacia el valor real:

  • Verde (Exacto): el marcador coincide con el resultado real.
  • Naranja (Cerca): umbral dinámico según el deporte — 2 goles en fútbol, 10 puntos en NBA y 5 puntos en NFL.
  • Rojo (Lejos): fuera del umbral de cercanía, indicando si el valor real es mayor o menor.

5 Modos de juego

6 Deportes

Además del reto global sincronizado, el motor soporta filtros históricos y dinámicas de velocidad:

  • Diario: el partido del día para toda la comunidad hispanohablante.
  • Clásico: encuentros históricos disputados antes de 1999.
  • Playoffs y Selecciones: fases eliminatorias y torneos internacionales.
  • Arcade: rondas contra reloj con sistema de vidas.
  • Tenis set a set: mecánica especializada donde se adivina el marcador de cada set.

Gamificación sin fricción

Zero-Auth

Experiencia completa de retención y progresión sin obligar al usuario a registrarse ni ceder datos personales:

  • XP y Niveles: progresión continua según precisión e intentos utilizados.
  • Rachas con «congelamientos»: protección de racha diaria ante días inactivos.
  • Logros y Sonido: desbloqueables locales y síntesis de efectos de audio.
  • Cuadrícula compartible: resumen visual libre de spoilers listo para redes y mensajería.

Protocolo Anti-Spoilers: HMAC-SHA256(puzzleId + fecha + intento)
Reintento de red → Respuesta idempotente · Token reusado → HTTP 409 Conflict · Modo Arcade → Estado firmado en el token (0 sesiones/cookies)

Verificación del lado del servidor

Zero Client Leaks
  • El cliente nunca recibe la respuesta antes de completar o agotar los intentos de la partida.
  • Cada intento viaja acompañado de un token firmado HMAC-SHA256 de un solo uso, ligado criptográficamente al puzzle, la fecha y el número de intento.
  • Un reintento legítimo devuelve la misma respuesta; un intento de reusar el token recibe un 409 Conflict.
  • El modo Arcade encapsula todo el estado de la partida (vidas, ronda, tiempo) dentro del propio token firmado, sin sesiones en servidor ni cookies.
  • Una prueba E2E automatizada inspecciona red, DOM y localStorage para garantizar cero fugas del marcador.

CSP estricta por hash y Base de Datos

Seguridad por diseño
  • Content Security Policy en build: una integración propia calcula el hash criptográfico de cada script y estilo inline al compilar y genera una CSP estricta por página, eliminando unsafe-inline para scripts.
  • API robusta: Hono sobre Node con validación de entorno al arranque, cabeceras de seguridad, respuestas de error bajo el estándar RFC 9457 (Problem Details) y logs JSON con pino.
  • SQLite en modo WAL: lecturas concurrentes de baja latencia y política de migraciones solo aditivas para que un despliegue nunca rompa la versión anterior durante el rollout.
04 · SEO Programático & Crecimiento

+500 páginas generadas con datos reales sin revelar respuestas

Arquitectura de adquisición orgánica diseñada tanto para buscadores tradicionales (Google, Bing) como para motores de respuesta basados en IA.

Páginas agregadas & Control de indexación

+500 Rutas Estáticas
  • Una página por equipo, liga y torneo con estadísticas reales agregadas calculadas en build.
  • Muestran promedios y tendencias históricas, nunca el marcador de un partido concreto, protegiendo la integridad de futuros puzzles.
  • Sitemaps segmentados por deporte y tipo de plantilla para diagnosticar con precisión la cobertura en Google Search Console.
  • Filtro de calidad automático: las páginas sin contenido suficiente se marcan como noindex y se excluyen de los sitemaps.

Datos estructurados, IA & Monetización

Schema.org + IndexNow
  • Rich Snippets: marcado Schema.org completo para FAQPage, HowTo y BreadcrumbList, además de tarjetas Open Graph.
  • Indexación instantánea: integración con IndexNow para notificar a Bing y otros motores al publicar cambios.
  • Optimizado para buscadores IA: archivo llms.txt estructurado y permisos explícitos para crawlers de IA en robots.txt.
  • Monetización verificada en CI: Google AdSense con plataforma de gestión de consentimiento (CMP) y Google Tag Manager; el build falla automáticamente si alguna página sale sin las etiquetas.
05 · Calidad, Infraestructura & Operación en Producción

CI estricto, despliegue propio en VPS Linux y mantenimiento real

El código se valida en cada push mediante presupuestos de rendimiento, pruebas multi-dispositivo y auditorías de accesibilidad WCAG AA antes de llegar a producción.

Suite de Calidad y Accesibilidad

Vitest + Playwright + axe
  • 250 tests unitarios con Vitest: el paquete compartido de reglas del juego exige al menos un 90 % de cobertura.
  • 77 pruebas E2E con Playwright: ejecutadas tanto en escritorio como en perfil móvil (Pixel 5), validando partida completa, flujo de compartir, ausencia de fuga de respuesta y accesibilidad con axe.
  • Análisis estático: ESLint con reglas de accesibilidad (jsx-a11y), TypeScript estricto y verificación de contraste WCAG AA.
  • Pipeline en GitHub Actions: lint, chequeo de tipos, tests unitarios, build, presupuestos de tamaño (<70 KB JS / <150 KB total), auditoría de dependencias y E2E en cada push.

Infraestructura y Gobierno Operativo

VPS Linux · Docker · Nginx
  • Despliegue propio en VPS Linux: orquestado con Nginx, systemd y Docker Compose.
  • Seguridad en despliegues: respaldos automáticos de la base de datos antes de cada cambio y verificación de salud (healthcheck) posterior al despliegue.
  • Documentación operativa: runbooks de respuesta a incidentes, registro de riesgos (RAID) y un panel de estado con el historial trazable de cada despliegue.

Migración mayor: Astro 4 → Astro 7

Seguridad & Paridad

Para cerrar alertas de seguridad en dependencias transitivas, ejecuté la migración completa del frontend desde Astro 4 hasta Astro 7. Para garantizar cero regresiones de SEO, CSP o hidratación, comparé la salida compilada del sitio anterior y el nuevo archivo por archivo antes de promover a producción.

Resolución de caída en producción (ABI Nativo)

Post-Mortem

Durante un despliegue diagnostiqué y resolví una caída de la API en producción provocada por un binario nativo incompatible (better-sqlite3 compilado contra una ABI distinta). Aislé la causa raíz en el entorno de empaquetado, restauré el servicio y dejé documentado el procedimiento en el runbook para prevenir recurrencias.
